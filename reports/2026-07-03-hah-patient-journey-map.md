## 一、执行摘要

本报告基于 MGB Home Hospital（全球最学术化的 HaH 项目）、Atrium Health Hospital at Home（全球最大规模，ADC 80-100）、DispatchHealth Advanced Care（最大独立纯 play 运营商）三者的公开患者旅程数据，合成一个**通用 HaH 患者旅程模型**。

**核心发现：**

1. **HaH 患者旅程与传统住院截然不同**——从"被动接受院内标准化流程"变为"主动参与居家个性化治疗"。这种范式转换既是最大优势（满意度 93-98 NPS），也是最大挑战（患者/家属需承担更多自我管理责任）。
2. **转化漏斗最窄点在"筛选→同意"阶段**——临床筛选标准（O2≤4L、生命体征稳定、无72h内高级诊疗需求）叠加患者意愿，使许多潜在候选者未能入组。Atrium 经验显示 ED 直接入组占 40%，住院转 HaH 占 60%。
3. **退出路径的临床安全性是关键信任基础**——MGB 0 意外死亡、DispatchHealth 0 严重安全事件，证明 HaH 即使在需要升级回院时也是安全的。
4. **照护者/家属的"隐形负担"是最大盲区**——现有 HaH 项目的家属支持系统性设计不足。法国 HAD 研究显示家属角色多变，从日常协助到医疗决策参与，但缺乏结构化支持。
5. **对 iHomeCare 的核心启示**：患者体验 = 临床安全 × 技术便利 × 人文温度。三个维度缺一不可。

## 二、方法论与数据来源

### 2.1 数据来源

| 来源机构 | 类型 | ADC | 关键数据点 |
|:---|:---|:---:|:---|
| **MGB Home Hospital** | 学术医疗系统自营 | 25-33 | RCT 证据、0 意外死亡、7% vs 23% 再入院率、Continuing Care 同团队模式 |
| **Atrium Health HaH** | 大型医疗系统自营 | 80-100 | 月均患者 154→379 增长、儿科 HaH、Payer-agnostic、C-suite "ALL IN" |
| **DispatchHealth Advanced Care** | 独立纯 play 运营商 | 未公开 | 93 NPS、98% 满意度、58% ER 替代、0 安全事件、$5K-7K/例节省 |

### 2.2 合成方法

对三家机构的患者旅程进行横向对比，提取共性阶段和差异化特征。共性的归入"通用模型"，差异化的在具体阶段标注来源。此方法遵循 Kate 调研方法论中的多源交叉验证原则。

### 2.3 关键假设

- 所有定量数据以公开来源为准；未公开数据标注「不可得」
- 通用模型中的时间轴基于急性内科 HaH 典型病程（2-7天）
- 儿科 HaH（仅 Atrium 覆盖）在通用模型中不详细展开

### 3.1 Phase 0: 急诊识别与评估（Day -1）

**触发场景：患者到达医院 ED 或因急性症状就诊于住院部。**

| 维度 | MGB Home Hospital | Atrium Health HaH | DispatchHealth | 通用模型 |
|:---|:---|:---|:---|:---|
| **临床行动** | ED 医生接诊，进行初步诊断和稳定治疗 | 同左——标准 ED 路径 | ⚡ 差异：患者可自行拨打热线/App请求上门（无需先到 ED） | ED 医生接诊 → 初步诊断 + 稳定治疗 |
| **决策点** | 🔑 ED 医生判断是否需要住院 → 若需住院，评估 HaH 适宜性 | 🔑 同左 + 住院部也可转诊 HaH | 🔑 远程评估（热线/App）→ 判断是否属于95% ER诊断范围 | **是否需住院？若需住院，是否适合 HaH？** |
| **筛选标准** | 「未完整公开」推测与同行一致 | 明确标准：O2≤4L、RR<24、SBP>90、SpO2>92、72h内无高级诊疗需求 | 病情属95% ER诊断 + 居家环境安全 | O2≤4L + 生命体征稳定 + 72h无高级需求 + 居家安全 |
| **人员接触点** | ED 医生、护士、Case Manager | ED 医生、HaH 协调员 | DispatchHealth 临床团队（远程） | ED 医生 → HaH 评估协调员 |
| **技术接触点** | EHR 系统内 HaH 筛选工具 | EHR 筛选 + HaH 团队通知 | DispatchHealth App/热线 + 保险验证系统 | EHR 筛选 + 保险验证 |
| **数据采集** | 生命体征、病史、诊断、保险信息 | 同左 + SDOH 初步筛查 | 自述症状 + 保险覆盖 + 地理范围 | 生命体征 + 病史 + 保险 + 地理 + SDOH |
| **痛点** | ⚠️ ED 医生可能不了解 HaH 或不愿转诊（"试点心态"风险） | ⚠️ ED 高负荷下 HaH 筛选可能被忽略 | ⚠️ 患者需主动联系——认知度是关键瓶颈 | **ED 医生的 HaH 意识和信任度是最大变量** |

> **Atrium 关键经验**：C-suite "ALL IN" 心态是解决 Phase 0 瓶颈的前提——"试点心态必死"（HFMA NC 2024）。

### 3.2 Phase 1: 入院评估与激活（Day 0）

**这是患者从"传统住院路径"切换到"居家治疗路径"的临界点——也是整个旅程中不确定性最高的阶段。**

```
┌─────────────────────────────────────────────────────────────────┐
│                      Day 0: 入院评估与激活                         │
│                                                                  │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐   │
│  │ 正式筛选  │ → │ 知情同意  │ → │ 设备部署  │ → │ 首次上门  │   │
│  │ HaH评估  │    │ 患者签字  │    │ RPM+平板  │    │ RN/急救员 │   │
│  └──────────┘    └──────────┘    └──────────┘    └──────────┘   │
│                                                                  │
│  患者情感:  "我真的可以在家治吗？" ──→ "这些设备怎么用？"           │
│             (犹豫、不安全感)           (技术焦虑)                   │
└─────────────────────────────────────────────────────────────────┘
```

| 维度 | 详细说明 |
|:---|:---|
| **临床行动** | ① HaH 临床团队最终评估筛选标准 → ② 主治医师与患者/家属沟通 HaH 方案 → ③ 获取知情同意并签署文件 → ④ 开具居家治疗医嘱（IV/O2/药物/PT/OT等） |
| **决策点** | 🔑 **患者同意/拒绝**——这是整个漏斗中最重要的单一决策点。影响因素：对HaH安全性的信任度、家属支持意愿、居家环境适宜性、数字素养 |
| **技术接触点** | RPM设备配送（Current Health可穿戴臂带 / Medically Home 平板 + 第三方血压/血氧/体温）+ 双向音视频设备安装 + 指挥中心连接测试 |
| **人员接触点** | HaH协调员、主治医师、设备技术人员（Cardinal Velocare/MH物流）、首次上门RN/社区急救员 |
| **设备部署** | Atrium: 平板 + RPM设备 + 双向视频；MGB: Current Health 臂带 + Cardinal配送；DispatchHealth: Medically Home平台设备 + 随车移动影像/实验室 |
| **数据采集** | 基线生命体征、完整用药清单、SDOH评估（家庭环境/照护者可用性/电话/紧急联系人）、数字素养评估 |
| **痛点** | ⚠️ **设备安装焦虑**——老年患者对技术设备不熟悉（MGB 研究特别关注老年队列） ⚠️ **"我被抛弃了吗？"**——部分患者感觉被医院"赶回家" ⚠️ **家属的顾虑**——"如果半夜出事怎么办？" |

> **MGB 差异化**：Home Hospital Continuing Care 由同一团队提供，消除转诊断点。

### 3.3 Phase 2: 急性期管理（Day 1-3）

**HaH 的核心治疗阶段——临床密集度最高、技术监控最紧密、患者/家属心理适应期。**

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Day 1-3: 急性期日常节奏                              │
│                                                                      │
│  08:00  RN/社区急救员首次上门（生命体征 + 用药 + 评估）                  │
│  10:00  MD 虚拟查房（视频）——"医生今天怎么样？"                         │
│  12:00  IV/呼吸治疗/实验室（按需）                                     │
│  14:00  RN/急救员第二次上门（如需）                                    │
│  全天   24/7 指挥中心持续远程监控 + RPM 实时数据传输                     │
│  全天   一键连接指挥中心按钮（患者平板/设备）                            │
│                                                                      │
│  患者情感:  担忧 → 适应 → "原来真的可以"（转折点通常在 Day 2-3）         │
└─────────────────────────────────────────────────────────────────────┘
```

| 维度 | Atrium Health HaH | DispatchHealth | MGB Home Hospital | 通用模型 |
|:---|:---|:---|:---|:---|
| **临床行动** | 每日2次上门（社区急救员/RN）+ MD每日虚拟查房 + IV/O2/呼吸治疗/EKG/实验室 | RN按需上门（频次基于病情）+ Hospitalist远程查房 + 移动影像/实验室 + PT/OT | MD 虚拟查房 + 上门RN（MGB自雇）+ IV/O2/影像/实验室/PT/OT/社工/餐饮 | **每日1-2次上门 + 每日MD虚拟查房 + 按需IV/实验室/影像/治疗** |
| **人员接触点** | 社区急救员（Paramedic）+ RN + MD（虚拟） | 医师/PA/NP + RN + 技术员 | MGB 自雇医师/RN/NP/PA | RN/急救员（上门）+ MD/NP/PA（虚拟）+ 指挥中心RN（远程） |
| **技术接触点** | RPM设备 + 双向视频平板 + 24/7指挥中心监控 | Medically Home 平台 + 指挥中心 + 个性化报警阈值 | Current Health 可穿戴 + Clinician Dashboard + AI 预警 | RPM设备 + 视频平台 + 指挥中心 |
| **数据采集** | 每次上门：生命体征 + 症状评估 + 用药依从性；持续：RPM实时数据流 | 每次上门：生命体征 + 体格检查 + POCT实验室；持续：远程监控 | Current Health 连续监测（HR/SpO2/活动/睡眠）+ 上门评估 | **离散（上门采集）+ 连续（RPM流）** |
| **决策点** | 🔑 **继续居家 vs 升级回院**——每日MD查房评估。触发升级条件：生命体征恶化、需高级影像/手术/ICU、患者/家属要求 | 同左 + 个性化报警阈值自动触发升级评估 | 同左 + AI 预警辅助决策（Current Health 算法） | 🔑 **每日"居家继续 vs 升级"决策** |
| **痛点** | ⚠️ 社区急救员 vs RN 的临床判断差异 ⚠️ 设备连接问题（WiFi/蓝牙） | ⚠️ 影像能力出售后依赖第三方 ⚠️ 整合阵痛期（DispatchHealth+MH平台） | ⚠️ 设备佩戴舒适度（可穿戴臂带） ⚠️ 假警报导致不必要焦虑 | **设备可靠性 + 升级路径清晰度 + 人力配置适当性** |

> **Atrium 人力模型创新**：用社区急救员（Paramedic）替代部分 RN 上门，降低成本的同时不牺牲质量。对 iHomeCare 的人力配置有直接参考意义。

### 3.4 Phase 3: 稳定期与康复管理（Day 4-7）

**临床密集度下降，患者从"被治疗者"转向"主动康复者"。**

| 维度 | 详细说明 |
|:---|:---|
| **临床行动** | 上门频次降低（如从 2次/日→1次/日→隔日）；IV 逐渐停用转口服药物；PT/OT 康复治疗；营养/社工服务（MGB特色） |
| **人员接触点** | RN/急救员（减频上门）+ MD（虚拟查房频率可能降至隔日）+ PT/OT/社工（按需）+ 指挥中心（持续） |
| **技术接触点** | RPM 持续监测（报警阈值可能放宽）；视频查房；患者 App 自我报告症状 |
| **数据采集** | 康复指标（活动量/饮食/疼痛评分/功能恢复）+ 用药调整 + SDOH 深度跟进 |
| **决策点** | 🔑 **出院时机判断**——临床稳定 + 达到康复里程碑 → 准备出院计划 |
| **痛点** | ⚠️ **"我还好吗？"**——监控减频可能引发患者不安 ⚠️ **家属疲劳**——多日照护可能导致照护者倦怠 ⚠️ **用药过渡**——IV→口服转换可能出错 |

> **MGB 亮点**：此阶段社工+餐饮服务介入，将 HaH 从纯医疗扩展为"医疗+社会支持"。DispatchHealth 32% 病例处理了SDOH（社会健康决定因素），说明社会因素在此阶段尤为关键。

### 3.5 Phase 4: 过渡与出院（Day 7+）

**从 HaH 急性治疗"毕业"，进入社区/术后护理体系。**

| 维度 | MGB | Atrium | DispatchHealth | 通用模型 |
|:---|:---|:---|:---|:---|
| **出院标准** | 临床稳定 + 自主活动能力恢复 | 临床稳定（同入院标准反向验证） | 临床稳定 + 治疗方案完成 | 临床稳定 + 功能恢复 |
| **出院动作** | 出院总结 → 转 **Home Hospital Continuing Care**（同一团队！） | 设备回收 → 转 PCP / 必要时转 Atrium Continued Health | 设备回收 → 转 DispatchHealth Transitional Care（高风险患者）/ PCP / Home Health Agency | **设备回收 + 出院总结 + 转后续照护** |
| **核心差异化** | 🟢 **同一团队负责急性期+出院后延续**——消除转诊断点 | 转 Atrium Continued Health（Advanced Care / Palliative Care） | 🟢 **自有三层连续服务**（ER替代→住院替代→过渡护理） | 出院后的衔接质量 = 防止再入院的关键 |
| **患者体验** | "还是同一个医生/护士，我放心" | "转到另一个团队了…要重新适应" | "他们还管我，太好了"（过渡护理模式下） | 转诊衔接的"信任连续性" |
| **痛点** | ⚠️ 同一团队虽好但可能资源紧张 | ⚠️ 转诊信息传递可能丢失 | ⚠️ 整合过渡（收购MH后） | **出院后衔接断裂是30天再入院的主要风险因子** |

### 3.6 Phase 5: 30天随访与闭环（Day 8-30）

| 维度 | 详细说明 |
|:---|:---|
| **临床行动** | PCP 随访（常规）+ HaH 团队随访电话/问卷 + Transitional Care 跟进（如入选）+ 用药依从性检查 |
| **技术接触点** | 电话随访 + 患者满意度问卷（HCAHPS/Press Ganey 类）+ 部分项目可能延长 RPM 监测 |
| **数据采集** | 30天再入院率、患者满意度/NPS、功能恢复评估、用药依从性 |
| **决策点** | 🔑 若再入院——分析原因（病情本身 vs 居家环境 vs 系统问题）→ 质量改进循环 |
| **闭环价值** | MGB 7% vs 23% 传统住院再入院率、DispatchHealth 8.5% 再入院率——这些指标反馈到筛选标准和临床路径优化 |

## 四、三大入口路径对比

HaH 患者并非只有一种"入口"。三种主要入口路径在早期阶段存在显著差异。

```
                    患者入口路径对比

   路径 A: ED→HaH                路径 B: 住院→HaH            路径 C: 社区→HaH
   ──────────────               ──────────────              ──────────────
   患者到ED就诊                  患者已住院治疗中              患者从社区被转诊
   │                            │                           │
   ├ 急诊医生初诊                ├ 住院医生评估               ├ PCP/Specialist识别
   │                            │                           │
   ├ 判断需住院                  ├ 判断可提前出院             ├ 联系HaH服务商
   │                            │  转HaH完成治疗             │
   ├ HaH筛选评估                 │                           ├ 远程/现场评估
   │                            ├ HaH筛选评估                │
   ├ 知情同意                   │                           ├ 知情同意
   │                            ├ 知情同意                   │
   ├ 设备部署+首次上门           ├ 从医院转运回家             ├ 设备部署+首次上门
   │                            │  + 设备部署                 │
   └ 进入Day 1-3急性期          └ 进入Day 1-3急性期          └ 进入Day 1-3急性期

   占比(Atrium): ~40%            占比(Atrium): ~60%           占比: <5%（DispatchHealth特有）
```

| 对比维度 | 路径 A: ED→HaH | 路径 B: 住院→HaH | 路径 C: 社区转诊→HaH |
|:---|:---|:---|:---|
| **适用场景** | 患者刚到ED，决定不住院直接回家治疗 | 患者已住院1-2天，病情稳定可提前出院完成疗程 | 社区PCP/Specialist/健康计划Case Manager识别患者需要住院级治疗 |
| **主要机构** | Atrium (~40%), MGB | Atrium (~60%), MGB | DispatchHealth (核心模式) |
| **优势** | ✅ 完全避免住院（最高价值） ✅ 患者从未体验"病床"，无对比落差 | ✅ 患者已稳定——风险更低 ✅ 医生有更多时间评估 ✅ 缩短住院日——释放床位 | ✅ 最便捷——患者无需出门 ✅ 扩大HaH可及性（不止ED/住院） |
| **劣势** | ❌ ED环境下的快速决策压力大 ❌ 患者/家属来不及充分了解HaH | ❌ "既然已住了两天，不如住完"的心理惯性 ❌ 转运物流成本 | ❌ 严重依赖社区医生的HaH认知 ❌ 没有ED/住院的"筛选前"评估 ❌ 误判风险更高 |
| **核心决策挑战** | "在30分钟ED评估内，说服患者/家属信任一个全新模式" | "证明提前出院+转HaH比继续住院更好" | "谁来判断这真的比去医院安全？" |
| **患者情感** | 焦虑峰值最高——"我不去病房？回家行吗？" | 惊喜/疑虑混合——"我可以提前回家了？" | 便利感强，但也有"他们真的能处理吗？"的担忧 |
| **对 iHomeCare 的启示** | 需要简化的决策辅助工具（可视化对比"医院 vs 居家"） | 需要床位管理团队（自动识别可转HaH的住院患者） | 需要社区医生教育+标准化转诊协议 |

### 关键数据

- **Atrium**：ED 直接入组 ~40%，住院转 HaH ~60%。说明大多数 HaH 患者是先住院再转——这可能是更安全的路径，但也意味着"完全避免住院"的比例还有提升空间。
- **DispatchHealth**：58% ER 替代率（即原本要去ER的患者58%完全避免了ER）。证明社区入口的高价值潜力。
- **MGB**：目标将 10% 内科患者转移至 HaH——说明即使在成熟项目中，大部分合格患者仍未进入 HaH 路径。

### 5.1 照护者旅程的五个阶段

| 阶段 | 照护者任务 | 情感状态 | 风险点 |
|:---|:---|:---|:---|
| **Day -1: 被告知** | 接收信息——家人需要住院级治疗，但可以选择居家。通常是被动接收者。 | 震惊、担忧、信息过载 | ❌ 被排除在决策过程之外 ❌ 无法充分理解 HaH 的含义 |
| **Day 0: 承诺** | 签字同意（有时需要家属签字）、接受设备培训、准备居家环境、请假/调整工作 | 责任感 + 焦虑——"我能胜任吗？" | ❌ 未充分评估照护者能力 ❌ 照护者仓促承诺但后期无法持续 |
| **Day 1-3: 承担** | 协助用药管理、配合上门团队、监测患者状况、与指挥中心沟通、处理紧急情况 | 压力快速上升——"我成了24/7护士" | ❌ 照护者角色不清（护士？家人？管理员？） ❌ 自身体力/情绪透支被忽视 |
| **Day 4-7: 疲惫** | 持续照护 + 自身的正常生活（工作/家庭）被搁置 | 疲惫 + 信心波动——"我还能撑多久？" | ❌ 照护者倦怠是最常见的隐性退出原因 ❌ 可能影响患者康复（照护质量下降） |
| **Day 7+: 回顾** | 恢复日常生活，反思经历 | 解脱 + 满足/后悔——"值得，但太累了" | ❌ 无系统的照护者 debrief/支持 ❌ 长期心理影响未被关注 |

### 5.2 现有项目的家属支持现状

| 机构 | 家属支持设计 | 评价 |
|:---|:---|:---|
| **MGB** | 「不可得」是否系统化——已知有社工/餐饮服务，但具体面向家属的支持未公开 | ⚠️ 可能部分覆盖但未系统化 |
| **Atrium** | SDOH 筛查含"家庭支持可用性"——入组标准要求"有能力配合或有居家支持" | ⚠️ 将家属作为"入组条件"而非"服务对象" |
| **DispatchHealth** | 32% 病例处理 SDOH——可能间接覆盖家属需求 | ⚠️ 以患者为中心的 SDOH 而非以家属为中心 |
| **法国 HAD 研究** | 照护者角色多变（日常助理→医疗决策参与→情感支持），存在"隐性痛苦" | 🔴 系统性缺失是全球普遍问题 |

### 5.3 关键洞察

> **"家属不是资源——家属也是用户。"** 
>
> 现有 HaH 项目将家属视为"入组条件"（有家属支持才能入组），但极少将家属视为独立的服务对象。照护者在 HaH 中承担的临床协助责任可能超过他们的能力或意愿——这是导致患者升级回院或退出 HaH 的隐性驱动因素。

### 6.3 MoT 的脆弱性

|:---|:---|:---|

| MoT-3 设备出问题 | 老年患者可能完全放弃使用 | 失去远程监控能力→被迫升级回院 |
| MoT-6 求救无响应 | 患者感受到"被抛弃"→直接打911 | 一次严重失败可能导致整个项目被质疑 |
| MoT-4 虚拟查房体验差 | 患者怀疑"医生有没有认真看" | 动摇对HaH"真医疗"的信任 |

### 7.1 各级转化率与瓶颈分析

| 漏斗层级 | 转化率（估） | 主要瓶颈 | 提升杠杆 |
|:---|:---:|:---|:---|
| **识别→筛选** | 30-50% | 临床医生对 HaH 的认知不足；筛选工具未嵌入 EHR 工作流 | ED/Hospitalist 教育 + EHR 内嵌 HaH 筛选提示 |
| **筛选→同意** | 50-70% | 🔴 **患者/家属对 HaH 安全性的信任不足**；"在家治病"的文化抗拒；数字素养 | 患者决策辅助工具（可视化对比 "医院vs居家"）；已出院患者的视频 testimonial；家属咨询支持 |
| **同意→入组** | 90%+ | 设备部署延迟；首次上门安排冲突 | 物流优化（Cardinal Velocare 模式）；当日设备部署能力 |
| **入组→完成** | 85-95% | 临床恶化需升级回院；患者/家属中途退出；AMA | 每日 MD 查房确保"继续 vs 升级"决策及时；家属支持干预 |
| **完成→满意** | 93-98% | 几乎无瓶颈——一旦完成，满意度极高 | 保持——这是 HaH 最不需要担心的环节 |

### 7.2 漏斗关键洞察

1. **最大瓶颈在"同意"而非"筛选"** ——HaH 的临床安全性和满意度已经数据证明，但公众认知远远滞后。MGB 目标将 10% 内科患者转入 HaH（当前远低于此），说明扩大漏斗的关键是**说服患者/家属**，而非放宽临床标准。
2. **"完成→满意"的极高转化率是 HaH 最强的武器**——93-98% 满意度意味着一旦患者体验过，他们就是 HaH 最有力的推广者。策略应是"让更多人体验第一次"。
3. **DispatchHealth 的社区入口（路径C）绕过了部分漏斗**——患者主动联系而非被动筛选，改变了"识别→筛选"的动力方向。但代价是误判风险和更高的临床筛选压力。

| **路径 1：完成治疗→出院** | 85-95% | 临床稳定 + 达到出院标准 | MGB 7% 30天再入院 (vs 23%传统)；DH 8.5% 再入院 | 🟢 最理想——患者满意、系统获益 |
| **路径 2：升级回院** | 5-15% | 生命体征恶化、需高级诊疗/手术/ICU、家庭环境不安全、照护者无法胜任 | DH 25% 过渡期升级预防率（主动升级避免恶化）；0 严重安全事件 | 🟡 虽非理想但证明了HaH的安全性——"升级"而非"失败"。DH 的 25% 升级预防率说明主动升级是系统设计的一部分 |
| **路径 3：AMA（Against Medical Advice）** | <3% | 患者/家属主动要求退出 HaH；与临床升级不同——这是意愿问题 | 「不可得」——三家均未公开 | 🔴 需追踪原因——是信任问题？家属负担过重？期望不匹配？ |
| **路径 4：死亡** | 极低 | 基础疾病进展——非 HaH 治疗导致 | MGB: **0 意外死亡**；DH: **0% 非预期死亡率** | 受控——与院内死亡率等同或更低 |

### 8.2 升级回院的时机与安全机制

| 机构 | 升级决策机制 | 升级触发标准 |
|:---|:---|:---|
| **Atrium** | 每日 MD 虚拟查房 + 24/7 RN 监控 + 指挥中心报警 | 生命体征恶化超预设范围；需高级影像/手术；需 ICU 护理 |
| **MGB** | Current Health AI 预警 + 每日 MD 查房 | AI 早期预警 + 临床判断 |
| **DispatchHealth** | Medically Home 指挥中心 24/7 + 个性化报警阈值 | 预设报警阈值 + 升级预防（25% 病例主动干预） |

> **关键洞察**：HaH 的"安全"不是指没有升级——而是**升级被及时、正确地触发**。0 意外死亡/0 安全事件的数据证明了三家机构的升级机制是有效的。HaH 升级回院不是"失败"，而是系统安全设计的正常组成部分。

## 九、对 iHomeCare 患者体验设计的建议

基于 MGB / Atrium / DispatchHealth 的综合分析，对 iHomeCare 的患者体验设计提出以下 10 条建议。

### 9.1 十大设计原则

| # | 原则 | 来源参考 | 具体建议 |
|:---:|:---|:---|:---|
| 1 | **"同一团队全程负责"** | MGB Continuing Care 模式 | 急性期治疗和出院后延续由同一团队负责，消除转诊断点。患者信任建立后不要中断。 |
| 2 | **"首次上门即信任锚点"** | MoT-2 的重要性 | 首次上门必须准时+专业+友好。配备统一制服、标准化问候、30分钟设备引导（而非扔下手册就走）。 |
| 3 | **"设备零门槛"** | MoT-3 设备恐惧症 | 面向老年用户的设计：大字体/一键连接/语音引导/家属辅助模式。参考 Current Health 可穿戴臂带——自动采集，无需操作。 |
| 4 | **"安全网可视化"** | MoT-6 求救无响应的恐惧 | 患者/家属需要**看到**他们被监控着——一个明确的状态指示灯或屏幕显示"指挥中心正在监控您"。DispatchHealth 的个性化报警阈值值得借鉴。 |
| 5 | **"家属不是资源，是用户"** | 第五节 照护者并行旅程 | 为家属提供独立 App/通道：照护者负担自评、休息提醒、与指挥中心直接沟通。照护者倦怠=潜在升级回院触发。 |
| 6 | **"决策辅助而非决策替代"** | 转化漏斗"同意"瓶颈 | 建立简化的视觉决策辅助（infographic 对比 "医院 vs 居家" 在安全/舒适/成本/恢复速度四个维度的差异），降低患者/家属的决策焦虑。 |
| 7 | **"出院不是结束"** | 3.5 过渡阶段 | 出院后48小时内的跟进电话是防止再入院的最关键干预。MGB 7% 再入院率 vs 23% 传统的差距，很可能部分来自 Continuing Care 的同一团队模式。 |
| 8 | **"社区入口捷径"** | DispatchHealth 路径C | 建立社区医生/PCP 的标准化转诊协议，让患者不需要先到ED也能进入 HaH。58% ER 替代率证明了这一路径的巨大价值。 |
| 9 | **"虚拟查房要有温度"** | MoT-4 | MD 虚拟查房不应只是"看着屏幕问问题"——屏幕共享展示检验结果、虚拟"白板"画病理、结束时给患者一个明确的"下一步"。 |
| 10 | **"用患者 testimonial 销售 HaH"** | 完成→满意 93-98% | 满意度最高的患者是最好的推广者。录制已出院患者的简短视频 testimonial，在 ED 筛选阶段播放给犹豫的患者/家属看。 |

### 9.2 患者体验设计路线图

```
Phase 1: 基础安全性（先做）
  ├─ 升级回院路径清晰化（患者/家属知道"什么情况下会回医院"）
  ├─ 指挥中心一键连接（响应时间 <5分钟）
  └─ 设备安装引导标准化（30分钟陪跑式引导）

Phase 2: 人性化体验（再做）
  ├─ 家属独立支持通道
  ├─ 虚拟查房体验优化（屏幕共享/可视化）
  └─ 决策辅助工具（infographic + testimonial）

Phase 3: 生态化闭环（终极）
  ├─ 社区入口（PCP 转诊协议）
  ├─ 同一团队全程负责（急性→延续→社区）
  └─ 患者社区/Peer Support（已出院患者与新患者结对）
```

### 9.3 关键 KPI 建议

| KPI | iHomeCare 目标 | 参考基准 |
|:---|:---:|:---|
| 患者 NPS | ≥70 | DH 93; 行业优秀 ≥50 |
| 30 天再入院率 | <10% | MGB 7%; DH 8.5%; 传统 23% |
| 筛选→同意转化率 | >60% | 当前行业估 50-70% |
| 首次上门准时率 | >95% | MoT-2 锚定信任 |
| 升级回院率（安全网使用率） | 5-15% | 太低=筛选过严/不敢收, 太高=筛选过松 |
| 家属 NPS | ≥60 | 当前无行业基准——iHomeCare 可首创 |
| 指挥中心响应时间 | <3分钟 | HaH Users Group 推荐 |
| 出院后48h随访完成率 | >90% | 防止再入院最有效干预 |

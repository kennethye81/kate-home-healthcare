## D1 — 执行摘要

## D3 — 战略定位

**核心逻辑**："**Bringing the power of the hospital to the comfort of home™**"——不依赖 JV 合同、不依赖单一卫生系统，自建全国性临床+物流+技术网络，直接面向患者和支付方。

**战略差异化要素**：

| 维度 | DispatchHealth（自营） | Contessa（JV） | Current Health（SaaS） |
|---|---|---|---|
| 临床团队 | **自雇**：APP + EMT + 远程 MD | JV 共享卫生系统 RN/MD | 无自有临床团队 |
| 物流/设备 | **自建**：Mobile Imaging + CLIA 移动实验室 | JV 共享 | 客户自行采购 |
| 支付方关系 | 直接签约：50+ 健康计划 | 通过 JV 间接 | 不直接接触支付方 |
| 客户关系 | B2B2C（付费方+患者） | JV 内 B2B | B2B SaaS |
| 扩张速度 | **快**（签署合同即可启动） | 慢（JV 谈判 12-24 月） | 最快（月付 SaaS） |
| 品牌强度 | DispatchHealth 品牌 | 融入本地卫生系统品牌 | 白标/CopilotIQ |
| 技术来源 | 自研 + Medically Home 平台 | CareConvergence 自研 | CurrentOS |

**战略演变三阶段**：
1. **Phase 1 (2013-2020)**：自建自营模型验证——从 Denver 起步，建立 APP+EMT 双人组上门服务模式
2. **Phase 2 (2021-2024)**：资本助推→快速规模扩张→50 都市区；同时面临盈利压力和估值挑战
3. **Phase 3 (2025+)**：与 Medically Home 合并→从纯服务提供商升级为"服务+技术平台"双引擎→整合阵痛期→目标成为 HaH 行业基础设施

## D8 — 工作流/旅程映射

```
Phase 0 — 需求触发
  患者不适 → 电话/App/网站预约
  或：健康计划 triage → DispatchHealth
  或：ER 过度拥挤 → 医院引导至 DispatchHealth
  或：911 呼叫 → 911 指挥中心识别非紧急案例 → DispatchHealth 分流
        ↓
Phase 1 — 评估与到达
  DH 调度中心 → 分配 APP + EMT 双人组 → 2-4 小时内到达患者家中
  携带 Mobile Lab + 诊断设备 + 药物
        ↓
Phase 2 — 服务交付
  APP 评估/诊断 → 治疗（IV 输液/抗生素/伤口护理等）
  → 远程 ER Physician 虚拟支持
  → 如需影像 → Mobile Imaging 到户
  → 处方直接送药上门
        ↓ （如为 Hospital-Level Care）
  → 每日 APP 查房 + 24/7 Command Center 远程监控
  → Medically Home 平台追踪生命体征/预警
        ↓
Phase 3 — 完成与过渡
  症状缓解/临床稳定 → 出院 → 3-7 天随访
  → 如需 Transitional Care → 30 天延续管理
        ↓
Phase 4 — 结算
  直接 Bill 保险公司（in-network）
  → 患者 co-pay $0-45（vs ER co-pay $100-500+）
        ↓
Phase 5 — 数据回传
  病例数据回传支付方/转诊医生 → 质量报告
  → Value-Based Care 财务结算（如有节省分成）
```

## D12 — 盈利模型与路径

### 成本结构拆解（估）

| 成本项 | 占收入比（估） | 特征 |
|---|---|---|
| 临床团队（APP/EMT/MD） | ~45-55% | 变动成本——随患者量线性增长 |
| 物流/车辆/设备 | ~10-15% | 半固定——车辆折旧+燃料+维护 |
| 技术平台 | ~5-8% | 固定（合并后可能降低） |
| 调度/指挥中心 | ~5-8% | 固定 |
| 保险/Billing/SG&A | ~10-15% | 半固定 |
| **经营利润率（估）** | **-5% 到 +5%** | 🟡 接近盈亏平衡但整合成本拖累 |

**盈利路径**：
- DispatchHealth 的"APP+EMT 双人组"模式在单次服务有正向毛利（vs 每次 ER 访问 $2000+ 费用）
- 但总部 SG&A、技术平台摊销、车辆折旧等固定成本需要极大患者量来分摊
- 合并后裁撤亏损市场 + 裁员是走向盈利的必经之路
- 如果 CMS 将 AHCAH 永久化 → 支付确定性提升 → 融资压力下降 → 盈利拐点

## D16 — 对 iHomeCare 战略建议

**DispatchHealth 是 iHomeCare 最重要的对标公司。** 其自营全栈模式验证了 HaH 不依赖 JV 也能运作——但代价是巨大资本需求。

| 维度 | DispatchHealth 教训 | iHomeCare 启示 |
|---|---|---|
| **模式选择** | 自营走通了——但烧 $700M+ | iHomeCare 应该走 **轻自营 × JV 混合**——HK 市场太小不适合纯自营 |
| **移动诊断** | Mobile Imaging + CLIA Lab 是壁垒 | **不做**——HK 密度高，患者去诊所更快 |
| **技术平台** | Medically Home 是核心资产 | 自研轻量指挥中心，不做 MH 级重型平台 |
| **支付方优先** | 50+ 计划签约→导流是关键 | iHomeCare 必须先签 HA+Bupa+AXA |
| **CEO 选择** | 创始人不做 CEO → 引入支付方背景外部 CEO | Kenneth 应该保留 CEO 但雇 COO 管日常运营 |
| **资本纪律** | $700M+ 融资后估值泡沫→现在痛苦 | **轻资本路线**——不需要对标 DH 的烧钱规模 |
| **警示** | 大合并后裁员是 HaH 整合的常态 | 未来如有并购机会：先做 100 天整合计划，不做口头承诺 |
